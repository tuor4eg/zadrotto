# Baseline схемы БД

С 4 ноября 2026 года активная цепочка Drizzle содержит один исходный `0000_baseline`. Предыдущие 162 миграции (0000–0161) вместе с исходными snapshot и journal находятся в [архиве](../../drizzle-archive/pre-baseline/). Архив не входит в путь migrator; исторические тесты читают его явно.

Источник декларативной структуры — [schema.ts](../../src/db/schema.ts). Активные SQL и snapshot созданы из этой декларации, поэтому имена ограничений соответствуют будущим изменениям Drizzle. Baseline дополнен `pg_trgm`, восемью прикладными функциями и девятью триггерами из схемы, полученной последовательным исполнением старой цепочки в чистой БД. Индексы, FK, уникальность и ограничения сохранены; новых путей запросов и изменений производительности нет. CHECK содержит SQL-литералы, а не bind-параметры: сохранённый SQL должен выполняться без параметров.

Baseline включает только безопасные исходные справочники и настройки 29 таблиц: типы носителей и записей, жанры и платформы с mappings, роли создателей, достижения, уровни и доверие, настройки регистрации, обложек, коллекций, email, toast, маршрутизации уведомлений, провайдеров и расписания jobs. Эти данные взяты из чистой БД старых миграций, без продовых данных. Счётчики соответствующих sequences перенесены. Администратор создаётся отдельной командой. Авторы, записи, оценки, серии, опыт авторов, provider snapshots, credentials и job runs не переносятся.

Новая пустая БД инициализируется `npm run db:migrate`. Следующие миграции генерируются обычным `npm run db:generate` относительно `drizzle/meta/0000_snapshot.json`; функции и триггеры по-прежнему требуют явного SQL при изменении. Архив не редактируется для будущих изменений схемы.

Существующая БД со старым migration journal не совместима с повторным исполнением baseline: автоматического переключения нет. Восстановление данных — отдельная процедура. Schema-only артефакт восстановления должен быть без bootstrap seeds. Нельзя просто загрузить data-only dump поверх seeded baseline: существующие строки конфликтуют с COPY, а активные триггеры оценок создают агрегаты. Для полного дампа следует восстанавливать pre-data, затем data, затем post-data, чтобы триггеры включились после загрузки. Production deployment этой сменой истории не выполняется.

Одноразовые CSV-генераторы игр и платформ по умолчанию пишут SQL в `.data/generated-imports/`, вне активной цепочки. Эти файлы требуют отдельной проверки и явного применения; они не воссоздают исторические миграции.
