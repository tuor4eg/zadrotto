# Фильтр потомков серии: проверка 2026-10-23

Включённый режим сохраняет прежний `publishedSeriesMembershipSql` без изменения
SQL. Для `seriesChildren=0` общий фильтр списка, total count и счётчиков типов
использует прямую опубликованную связь с опубликованной серией:

```sql
exists (
  select 1 from media_item_franchises series_link
  inner join franchises series on series.id = series_link.franchise_id
  where series_link.media_item_id = media_items.id
    and series_link.franchise_id = $1
    and series_link.publication_status = $2
    and series.publication_status = $3
)
```

Параметры: ID выбранной серии, `published`, `published`.
Дополнительных запросов для переключателя нет: используется уже загруженная ветка.

## Измерение

PostgreSQL 17.2, изолированные временные таблицы в тестовом контейнере.
100 000 записей, 1 002 серии, 1 029 701 связей, по 10 связей на запись;
популярная серия дополнительно связана с первыми 30 000 записями, имеет 10 детей.
После заполнения выполнен ANALYZE. Данные приложения не менялись; транзакция
завершена ROLLBACK. SQL условия получен через PgDialect из рабочего helper.
Для обоих режимов выполнен EXPLAIN (ANALYZE, BUFFERS): total count,
GROUP BY media_type и страница с ORDER BY release_year,id LIMIT 24 OFFSET 24.

| Случай | С потомками: count / типы / список, мс | Прямые: count / типы / список, мс |
| --- | --- | --- |
| Популярная серия | 1142 / 540 / 485 | 34 / 36 / 38 |
| Обычная серия, 1000 связей | 443 / 419 / 421 | 19 / 19 / 19 |
| Опубликованная без связей | 382 / 413 / 419 | 0.06 / 0.04 / 0.10 |
| Неопубликованная с одной связью | 262 / 269 / 281 | 0.04 / 0.04 / 0.09 |

Прямой режим использует существующий индекс (franchise_id, media_item_id),
проверку серии по PK, semi join и для страницы ограниченную сортировку.
Нет коррелированного обхода на каждую запись или новых N+1 запросов.
Прежний рекурсивный режим строит hashed subplan однократно, сканирует все
связи; высокий estimated cost включает JIT (531 мс у первого count).
Это существующая стоимость, оптимизация рекурсивного режима сюда не входит.
Новые индексы и миграции не нужны.

## Ограничения

Это сравнительная проверка изменяемого условия, не полный end-to-end benchmark
архива: временные таблицы используют text вместо enum; нет metadata/rating joins,
персональных фильтров и дополнительных запросов страницы. Холодный/прогретый кеш
и JIT влияют на времена. Измерения не предсказывают задержки production.
