# Пагинация создателей в админке

`getCreators` используется страницей `/admin/creators`. Страница не показывает число публичных
записей создателя, поэтому из выборки удалён неиспользуемый `mediaItemsCount`. Прежний
коррелированный подсчёт обходил `media_items` с проверкой прямых/писательских связей для
каждого создателя; проекция могла вычисляться также для строк, отбрасываемых OFFSET.
Публичные счётчики в `getPublicCreatorsPage` сохранены.

Миграция `0142_creator_admin_pagination` добавляет B-tree
`creators_display_name_order_idx (coalesce(name_ru,name),id)`, точно соответствующий
сортировке списка. ID сохраняет однозначный порядок одинаковых имён. Нумерация страниц,
поиск и фильтры не меняются. Провайдерные варианты и привязки загружаются только для ID
текущей страницы существующими пакетными запросами.

## Проверка

PostgreSQL 17, изолированная схема: 100 000 создателей (10% организаций, 50% русских имён),
100 000 записей (10% черновиков), 500 000 прямых участий, 1000 назначений псевдонима и 1000
связей псевдонимов. Выполнен ANALYZE. Поисковые GIN взяты дословно из миграций 0140/0141.

Проверены сгенерированные SQL и `EXPLAIN (ANALYZE,BUFFERS,FORMAT JSON)` обоих запросов:
общего количества и страницы. Старый запрос на страницах 1 и 1000 отменён по
statement_timeout 2 секунды; для него сохранён EXPLAIN без исполнения. Это нижняя граница
длительности, а не измерение полного выполнения.

После удаления неиспользуемого счётчика, до/после индекса сортировки:

| Страница, 24 строки | Без индекса | С индексом |
| --- | ---: | ---: |
| 1 | около 32 мс | 0,066 мс |
| 1000 | около 88 мс | 9,84 мс |
| 4000 | около 148 мс | 41,3 мс |

Обычный список использует Index Scan по индексу сортировки без Sort; отдельный count
занимает 22–26 мс. Редкое и отсутствующее поисковые совпадения используют нормализованные
GIN: около 0,08–0,10 мс на запрос. Проверены частое совпадение, фильтры типа/роли,
пустая выдача и ограничение слишком большого номера последней страницей. Два SQL-запроса
на список независимо от числа строк; запрос страницы больше не обращается к `media_items`.

Ограничения: OFFSET всё ещё линейно проходит предыдущие индексные строки. Точный count
растёт с размером выборки. Фильтр роли сохраняет существующий массовый расчёт прямых и
писательских связей (около 0,6–1,3 с на страницу в этом прогоне плюс 0,57 с count);
добавление индекса не меняет его план. Времена локальные и не являются SLA приложения.

Воспроизведение: `tests/creator-admin-pagination-runtime.test.ts`, переменная
`CREATOR_ADMIN_PAGINATION_TEST_DATABASE_URL` с отдельной тестовой БД; среда
`NODE_PATH=./node_modules/next/dist/compiled NODE_OPTIONS=--conditions=react-server`.
Тест сам создаёт и удаляет схему, сохраняет SQL/планы в
`/tmp/creator-admin-pagination-plans.json`. Production build не требуется.
