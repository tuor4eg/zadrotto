# BoardGameGeek

BGG — провайдер `bgg` для типа `boardgame`. XML API2 вызывается только сервером;
игры и дополнения становятся обычными записями. Издания и связи дополнений не импортируются.

## Настройка

1. Проверить лицензию одобренного приложения для фактического использования проекта:
   https://boardgamegeek.com/using_the_xml_api и https://boardgamegeek.com/xmlapi/termsofuse.
2. Проверить `REDIS_URL` и существующий `COVER_PROVIDER_CREDENTIALS_KEY` (не менее 32 символов).
3. В `/admin/tools/providers` сохранить BGG Application Token. Токен шифруется существующей
   системой credentials; `BGG_API_TOKEN` не используется. Не переносить токен в репозиторий,
   клиентский код или диагностические сообщения.
4. Включить поиск записей для BoardGameGeek и выполнить проверку подключения. Проверка
   всегда обращается к API, обходя кеш данных, но соблюдая общий интервал запросов.
5. Поиск обложек по умолчанию выключен. Включить его в общей админке только после
   подтверждения прав использования изображений. До этого превью BGG в результатах скрыты.
6. Сверить локальный Powered by BGG с официальным asset одобренного приложения;
   происхождение текущей публичной копии записано в `public/providers/bgg/README.md`.

Откат: выключить провайдер в общей админке. Сохранённые записи и обложки не удаляются.

## Поиск и данные

Поисковое поле принимает название, `bgg:822` или
`https://boardgamegeek.com/boardgame/822/carcassonne`.
Произвольные ссылки не загружаются. Кириллица отправляется в API без транслитерации.
Поиск по всем альтернативным русским названиям не гарантируется; при отсутствии результата
использовать оригинальное название либо ссылку/ID. В aliases предлагаются только названия
с кириллицей; общий лимит aliases сохраняется. Альтернативные названия в facts не сохраняются.

Полный исходный XML карточки `thing` по одному ID сохраняется строкой в `provider_snapshots`
с `contentType: application/xml`, точным descriptor и hash. Получение метаданных не использует
Redis-кеш разобранных карточек как raw; поиск и обложки сохраняют прежний кеш.
Категории идут в существующие соответствия жанров и очередь неизвестных значений.
Из снимка в JSON `facts` извлекаются механики, названия издателей, тип настолки/дополнения,
возраст, число игроков и продолжительность. Новых справочников механик и связей издателей нет.
После применения `bggSnapshotProcessed` подтверждает переход; дубли авторов, художников и жанров
удаляются из JSON, совместимое чтение получает их из рабочих связей и pending occurrences.
Отдельный `bggSnapshotHash` фиксирует применённый ответ: обновление raw само по себе не разрешает
использовать новый состав для повторной модерации. При несовпадении hash требуется проверенный
перенос совпадающего снимка либо явное применение изменений. SQL-миграции не требуется.
Подписанный источник после получения полной карточки обновляется для корректного снимка
провайдера, включая случай, когда превью карточки не удалось загрузить во время поиска.

Повторный импорт использует существующую проверку названий/aliases и года среди
опубликованных записей. Уникальность BGG ID в БД не обеспечивается. Редактирование названия,
отсутствующий год, приватные записи и параллельные импорты сохраняют прежние ограничения.
Автоматическое обновление устаревших настолок не включено; ручное получение метаданных
работает по сохранённому BGG ID. Получение метаданных не заменяет автоматически обложку.

## Перенос существующих настолок

В `/admin/tools/providers/snapshots` доступны объект «Настольные игры», BGG и операции
получения raw, обработки, получения с обработкой и проверки. Есть диапазон, партии,
checkpoint, отмена и фильтр отсутствующих точных снимков.

По умолчанию обработка выполняет проверенный перенос: сверяет BGG ID и роли `designer`/`artist`,
существующие occurrences/привязки/исключения, жанровые соответствия и рабочие характеристики.
Совпавшая запись получает маркер и очистку дублирующих ключей без пересоздания связей,
изменения заявок или постановки downstream jobs. Повторный перенос того же снимка — no-op.
При отличии запись остаётся прежней; отчёт показывает причины и ссылку для просмотра XML.
Полная синхронизация разрешается отдельной отметкой `applyBoardgameChanges:true`.
`process` работает без сети; `refresh` только сохраняет и привязывает raw.

Массовые операции не меняют название, aliases, описание или обложку. Русские альтернативные
названия по-прежнему предлагаются только при ручном выборе BGG в формах администратора и автора;
существующие варианты объединяются с предложенными через общую нормализацию и лимит aliases.

## Запросы и кеш

- Search: 15 минут, пустой результат — 1 минута.
- Thing: отдельная карточка по ID — 24 часа; отсутствующий ID — 1 минута.
- Обогащение результатов: один пакет максимум 20 ID; лимит UI обычно 8.
- Превью изображений: обязательный серверный relay, Redis-кеш 24 часа.
- Выбранные обложки: существующее S3/MinIO-хранилище и миниатюры.
- Разделение кеша XML при смене credentials; сам токен в Redis не сохраняется.
- Межпроцессное объединение запросов через Redis leases и общий минимальный интервал 5 секунд.
- Redis недоступен: запросы к BGG не выполняются; ошибка проверки лимита.
- Ошибки не сохраняются как данные. HTTP 202 откладывает snapshot job без расходования попыток записи; 429 учитывает Retry-After; временные отказы вводят
  cooldown. Автоматических повторов внутри формы нет. Общий таймаут по умолчанию 15 секунд.
- Существующая суточная статистика считает операции адаптера, а не внутренние HTTP-запросы.

XML ограничен 2 МБ; DTD, пользовательские entities, HTML challenge и неверные ID отвергаются.
Разрешённый CDN изображений: `cf.geekdo-images.com`, HTTPS, без редиректов на другие хосты.
URL вне allowlist даёт отсутствие обложки; allowlist расширяется только после проверки.

## AI

BGG-записи не отправляются в AI-справки и исключаются из примеров для подбора серий.
AI-подбор серий для настолок отключён на сервере и скрыт в формах: несохранённые поля
могут происходить из BGG даже при отсутствии метаданных. Это ограничение сохраняется до
подтверждения допустимости использования данных в AI.

## Проверка перед публичным включением

Тесты `tests/bgg-provider.test.ts` используют синтетические XML-фикстуры и не доказывают
работоспособность авторизации или русского поиска на живом API.
После настройки токена проверить через обе формы и записать фактические результаты:

| Запросы | Проверка |
|---|---|
| Carcassonne / Каркассон | Одинаковый ID |
| Catan / Колонизаторы | Альтернативное название |
| Wingspan / Крылья | Кириллица и резервная ссылка |
| Gloomhaven | Все доступные метаданные |
| Dune: Imperium / Дюна: Империя | Пунктуация |
| Evolution / Эволюция | Правильная игра среди одноимённых |
| Imaginarium / Имаджинариум | Нужная российская игра |
| Carcassonne: Inns & Cathedrals | Дополнение как отдельная запись |

Проверить сохранение без обложки, повторный импорт опубликованной записи, обновление
метаданных, видимость атрибуции и отсутствие прямых запросов браузера к BGG CDN.
Не считать регистрацию приложения разрешением на все изображения или изменение текста;
согласовать эти условия перед публикацией импортированных материалов.

### Исключение: локализация имён персон

Для сценария `creator_name_localization` разрешена передача только имени персоны, её роли
и названия связанной настольной игры для идентификации. Описания, изображения, тексты,
структурированные ответы API и другие материалы BGG в этот сценарий не передаются.
Исключение не отменяет запрет AI-справок, подбора серий и иных способов использования BGG в ИИ.
