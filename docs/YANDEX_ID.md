# Яндекс ID

## Настройка

1. Создайте приложение [для авторизации пользователей](https://oauth.yandex.ru/client/new/id/) в Яндекс OAuth, заполните сведения о сервисе и выберите платформу «Веб-сервисы».
2. Добавьте Redirect URI, который показан в «Админка → Инструменты → Авторизация». Он строится только из origin серверного `SITE_URL` и пути `/author/auth/yandex/callback`, без завершающего слеша.
   В текущем локальном `.env` указан `SITE_URL=https://zadrotto.online`: Redirect URI — `https://zadrotto.online/author/auth/yandex/callback`.
   Для домена из `.env.example`: `https://zadrotto.guskov.dev/author/auth/yandex/callback`.
   Для локального `SITE_URL=http://localhost:3000`: `http://localhost:3000/author/auth/yandex/callback`.
3. Выберите права «Логин, имя и фамилия, пол» (`login:info`) и «Портрет пользователя» (`login:avatar`). Email, телефон и дату рождения запрашивать не нужно.
4. Скопируйте Client ID и Client Secret в административную форму и включите провайдер. Используется существующий серверный `COVER_PROVIDER_CREDENTIALS_KEY`; отдельный ключ не нужен.
5. При повторном сохранении пустой Client Secret сохраняет прежний. Для ротации введите новый. Client ID нельзя менять, пока существуют связанные аккаунты.

Без обязательных credentials, корректного ключа или при отключённом провайдере кнопка не отображается и прямой вход недоступен. Сохранение настроек не проверяет credentials у Яндекса: проверка происходит при реальном входе. Сохранённый секрет не возвращается в браузер.

Документация Яндекса: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-auth), [Authorization Code + PKCE](https://www.yandex.ru/dev/id/doc/ru/codes/code-url), [профиль пользователя](https://yandex.ru/dev/id/doc/ru/user-information). Верификация сервиса убирает предупреждение Яндекса перед выдачей согласия.

## Ручная проверка

- В чистом браузерном профиле откройте `/author/login`, выберите Яндекс ID и подтвердите согласие. Создаются один автор, внешняя идентичность и обычная локальная сессия.
- Выйдите и войдите тем же Яндекс ID: должен открыться тот же профиль. Измените имя и аватар вручную и повторите вход: ручные значения должны сохраниться.
- В существующем аккаунте откройте профиль и нажмите «Подключить Яндекс ID». После согласия появляется способ входа; имя и аватар существующего профиля не меняются. Выйдите и войдите через привязанный Яндекс ID.
- Отмените согласие, повторно откройте уже использованный callback, отключите провайдер после начала входа: новая сессия не должна создаваться. Повторите вход с начала после восстановления настроек.
- Проверьте конфликт привязки к другому аккаунту, отключение способа входа при наличии альтернативы и запрет удаления последнего доступного способа.
- Проверьте выключение/включение в админке и отсутствие секретов в ответах страницы, публичном `/author/auth/providers` и журнале активности. Действующие локальные сессии отключение провайдера не отзывает.

## Миграция и выпуск

Миграция `0158_auth_provider_settings` относит все существующие credentials к `content`, сохраняет ciphertext без изменений и заменяет ключ на `(purpose, provider_code)`. Старый AES-GCM v1 читается прежним способом; auth использует v2 с AAD назначения и провайдера. Чтение и сохранение контентных credentials обновлены одновременно.

Остановите приложение и workers, примените миграции, запустите обновлённый код. Старые процессы нельзя оставлять с новой схемой: их `ON CONFLICT (provider_code)` больше не соответствует ключу таблицы, а чтение не фильтрует назначение. Отдельный откат только кода на старую версию недопустим; восстановление схемы и кода должно быть согласованным.

Автоматические тесты используют подмену HTTP, отдельный тест шифрования и изолированную тестовую PostgreSQL при заданном `EXTERNAL_AUTH_TEST_DATABASE_URL`. Они не заменяют ручную проверку зарегистрированного OAuth-приложения.
