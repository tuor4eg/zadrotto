# Публикатор событий квизов

## Кратко

Использовать существующую цепочку `domain event → consumer → transport outbox → job → transport`, отделив публичные публикации от персональных in-app уведомлений.

Уже готовы Telegram-конфигурация, маршрутизация, шифрование token, тестовая отправка, надёжный outbox, lease, retry и фоновые jobs. Нужно добавить события жизненного цикла квиза, их планировщик, форматирование публикаций и четыре независимых маршрута.

## Основные изменения

- Добавить domain events:
  - `quiz.started`;
  - `quiz.winner-selected`;
  - `quiz.ended`;
  - `quiz.cancelled`.
- Payload хранит минимальный публичный снимок, необходимый для отложенной доставки: вопрос, имя победителя либо название и code правильной записи. Это позволит доставить сообщение после изменения или удаления квиза.
- Добавить таблицу идемпотентных переходов квиза с ключом `(quiz_id, event_type)` для `started`, `ended`, `cancelled`.
- Добавить ежеминутный job:
  - публиковать старт только для реально активного включённого квиза;
  - публиковать окончание только если старт ранее был зафиксирован;
  - не публиковать задним числом квиз, целиком пропущенный во время простоя;
  - использовать блокировку и уникальный ключ для защиты от повторов.
- Событие победителя создавать в существующей транзакции первого правильного ответа только при фактическом `isWinner = true`.
- При отключении или удалении начавшегося квиза:
  - до `endsAt` создавать `quiz.cancelled`;
  - после `endsAt` создавать `quiz.ended`, если минутный job ещё не успел;
  - повторное включение отменённого квиза не запускает новый цикл.
- После опубликованного старта запретить менять вопрос, изображение, ответ, типы и начало. Разрешить комментарий и перенос `endsAt` только вперёд, пока квиз ещё активен и не завершён/отменён.

## Публикатор и маршруты

- Добавить отдельный consumer публичных публикаций, не создающий in-app уведомления.
- Переиспользовать существующий transport outbox, retry-policy и Telegram adapter.
- Обобщить разрешение внешнего сообщения так, чтобы delivery поддерживал и текущие уведомления, и публичные quiz events без жёсткой привязки к Telegram.
- Добавить независимые маршруты:
  - «Начало квиза»;
  - «Победитель квиза»;
  - «Правильный ответ»;
  - «Квиз отменён».
- Новые маршруты после миграции выключены. Администратор явно включает Telegram для каждого.
- Сообщения первой версии — простой текст:
  - старт: объявление, вопрос при наличии, ссылка на `/quizzes`;
  - победитель: публичное имя победителя и ссылка на `/quizzes`;
  - окончание: правильная запись и ссылка на `/media/{code}`;
  - отмена: сообщение об отмене без раскрытия ответа.
- Изображения и Telegram `sendPhoto` в первую версию не входят.
- Новые транспорты в дальнейшем добавляются через transport catalog/dispatcher, не через ветвления в quiz consumer.

## Проверка

- Миграция: ограничения типов, уникальность переходов, внешний ключ и индекс для поиска необработанных границ.
- Lifecycle-job: старт и окончание создаются один раз, конкурентные запуски не дублируют события.
- Победитель: событие получает только первый правильный ответ.
- Отмена: отключение и удаление начавшегося квиза дают одно сообщение; повторное включение не создаёт новый старт.
- Границы времени: допустимая задержка до одной минуты; просроченный целиком квиз не публикуется.
- Редактирование: после старта разрешены комментарий и продление, остальные публичные поля заблокированы.
- Маршрутизация: каждый из четырёх типов независимо включается для Telegram; по умолчанию всё выключено.
- Доставка: повторные попытки, частичный сбой получателей, потеря lease и идемпотентность сохраняют существующее поведение.
- Регрессия: текущие in-app уведомления, заявки и багрепорты продолжают работать без изменений.

## Принятые допущения

- Публичное имя победителя допустимо публиковать в Telegram-канале.
- `/quizzes` остаётся целевой страницей, даже если для неё требуется авторизация.
- Публикатор не является частью основной модели квиза: недоступность транспорта не блокирует ответы, выбор победителя, окончание или административные действия.
